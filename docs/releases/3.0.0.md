# szkrabok 3.0.0

Security hardening of the MCP server. **Breaking:** with no flags, the
server starts in a fail-closed posture. A client can no longer run Node code
on the host, read host files through the browser, navigate to literal
loopback or private addresses, or make tools write outside the server's work
root. Each capability that was on before is now a host-side flag in the
server command, never a tool argument. The address block is defence in
depth, not a network boundary (see Navigation below). The CLI (`szkrabok
<command>`) is not affected by the flags.

Design and audit:
[hardening proposal](https://github.com/PabloVitasso/szkrabok/blob/v3.0.0/docs/features/20261024-claude-docker-hardening-proposal.md).

## Upgrade in one line

On a desktop where you trust your projects, this gives the 2.x behaviour
back:

```bash
claude mcp add szkrabok -- npx -y @pablovitasso/szkrabok --trust-project-config --allow-node-code
```

Add `--allow-private-net` if you browse `localhost` or private-network
addresses. Never use these flags for a sandboxed or untrusted client.

## Server flags (new, argv only)

| Flag | Grants |
|---|---|
| `--work-root <dir>` | the only directory tools write to: `<dir>/sessions/` and `<dir>/reports/`. Default: cwd |
| `--spec-root <dir>` | confined `browser_run_test` / `session_run_test` (config and specs only from `<dir>`); page-mode `browser_run path` from `<dir>` |
| `--allow-node-code` | Node-form `browser_run`, `scaffold_init`, unconfined test tools |
| `--trust-project-config` | load `szkrabok.config.toml` from the project (MCP roots / cwd) |
| `--allow-private-net` | navigate to loopback and private addresses |

The server refuses to start if either root is relative or missing, if the two
roots overlap, or if a `--allow-*` / `--trust-*` flag is unknown (exit code
2, message in `~/.cache/szkrabok/startup.log`). `session_manage list`
reports the active flags and capabilities in `server`, and the config source
and ignored project configs in `config`.

## Breaking changes

- **`browser_run`** runs in the page by default: `code` is a function
  expression `(args) => result` with a JSON-serializable result. The Node
  form `(page, args)` and `fn` need `--allow-node-code`. `path` needs
  `--spec-root` (page mode, file from the spec root) or `--allow-node-code`.
- **`scaffold_init`** needs `--allow-node-code`.
- **`browser_run_test` / `session_run_test`** need `--spec-root` (confined)
  or `--allow-node-code` (unconfined). In confined mode:
  - `config` and `files` resolve inside the spec root only;
  - the run gets `--output <work-root>/reports/<session>/test-results` and
    `--update-snapshots=none`, so nothing is written into the spec root;
  - `reportFile` is a bare `*.json` name, written under
    `<work-root>/reports/<session>/`.
- **Test params:** each param reaches the spec as `SZKRABOK_PARAM_<KEY>` (key
  uppercased), not `<KEY>`. Specs reading `process.env.FOO` must read
  `process.env.SZKRABOK_PARAM_FOO`. Keys must match `^[A-Z][A-Z0-9_]*$` after
  uppercasing. Reserved names are refused: runtime, loader, package manager,
  shell and interpreter variables, `SZKRABOK_*` and `PLAYWRIGHT_*`. Values are
  strings, finite numbers or booleans, at most 4096 chars. The spec no longer
  inherits the server's `NODE_OPTIONS` or `npm_*` variables.
- **Config:** in server mode, `szkrabok.config.toml` in cwd or in MCP roots is
  ignored without `--trust-project-config`, and `.env` is never loaded. Use
  `--config`, `SZKRABOK_CONFIG`, `SZKRABOK_ROOT` or
  `~/.config/szkrabok/config.toml`. The CLI still loads `.env`.
- **Sessions:** in server mode they live in `<work-root>/sessions`, which
  overrides `SZKRABOK_SESSIONS_DIR`. Names must match
  `^[A-Za-z0-9][A-Za-z0-9._-]*$` (at most 64 chars). `session_manage delete`
  takes exact names only (no globs). `_`-prefixed `launchOptions` are dropped.
- **Navigation:** `file:`, `chrome:`, `data:` and other non-web schemes are
  always refused, at open and on later navigation (the main frame is reset to
  `about:blank`). Loopback and private addresses are refused without
  `--allow-private-net`. This blocks literal addresses only; a public hostname
  that resolves to a private address still connects. Treat it as defence in
  depth, not a network boundary.
- **Unconfined test runs** (`--allow-node-code`) write default reports to
  `<work-root>/reports/<session>/`, no longer `dirname(config)/sessions/<session>/`.
- **No registry fetch:** test runs use the project's
  `node_modules/.bin/playwright`, falling back to `npx --no-install playwright`.

## Fixes

- A transient popup closing during launch no longer kills the run with an
  unhandled rejection from the stealth user-agent override. The skipped call
  is logged with the page URL.
- localStorage restore at launch is best-effort per origin: one unreachable
  origin no longer aborts the launch.
- The Puppeteer-only `user-data-dir` stealth dependency no longer loads, so
  launches stop creating `/tmp/puppeteer_dev_profile-*` dirs. It also cannot
  be re-enabled through config.

## Library users

`spawnClient` (MCP client library) starts its private server with
`--allow-node-code --allow-private-net` as a trusted host context, and sets
`SZKRABOK_ROOT=<caller cwd>` unless `SZKRABOK_CONFIG` or `SZKRABOK_ROOT` is
already set. `spawnClient({ args, env })` replaces the flags and adds env.
