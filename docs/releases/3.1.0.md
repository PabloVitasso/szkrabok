# szkrabok 3.1.0

Stealth fixes and a security default. The browser now runs with its Chromium
sandbox on, the UA-CH client hints stop leaking the binary's build, and
service/shared workers report the same user agent as the page. The
`playwright-core` patch that greases the brand list is now szkrabok's own,
separate from the rebrowser patches.

## Upgrade

```bash
npm install -g @pablovitasso/szkrabok@3.1.0
szkrabok doctor            # confirms the playwright-core patch is in place
```

Reinstall rather than update in place: the postinstall chain changed, and the
patch is applied at install time. An install that skipped scripts reports
`playwright-core is not stealth-patched` on launch and in `szkrabok doctor`.

## Behaviour changes

### Chromium sandbox on by default

`chromiumSandbox` is now `true` at the launch boundary. Playwright adds
`--no-sandbox` unless it is true, so every host-mode browser previously ran
without its sandbox — a renderer exploit got the user's rights.

Opt out only where the environment is already the sandbox (a container with
seccomp and dropped capabilities):

```toml
[browser]
chromium_sandbox = false
```

Config-only, whole-server, restart-required. Firefox ignores the key.

Playwright's bundled Chromium ships no SUID sandbox helper, so on a host that
restricts unprivileged user namespaces (Ubuntu 23.10+ with
`kernel.apparmor_restrict_unprivileged_userns=1`) a sandboxed launch aborts with
Chromium's own `Chromium sandboxing failed!`. That is fail-closed by design, and
the error now names the opt-out and the resolved config path instead of leaving
you with the browser's message alone.

Measured on Ubuntu 24.04 with the userns restriction, flatpak Chromium 155 as
the resolved browser: with the default, `chrome://sandbox` reports "You are
adequately sandboxed"; with `chromium_sandbox = false`, "You are NOT adequately
sandboxed".

### UA-CH: no more binary-build leak

`calculateUserAgentMetadata` now sets `fullVersionList`, `fullVersion` and
`bitness`, so `Sec-CH-UA-Full-Version-List` reports the version the user agent
claims instead of the installed binary's build.

Residual, documented as risk 10 in the verified-core plan: when the configured
user agent is synthetic (`Chrome/120.0.0.0`), the full version list is
`120.0.0.0`, which differs from a real Chrome build (`120.0.6099.x`). The leak
is closed; the value is still not a real build number.

### Workers match the page

Playwright's `userAgent` option only overrides the page target, so service and
shared workers kept `HeadlessChrome/…`. The launch now passes
`--user-agent=<effective UA>` (mirroring the stealth plugin's `maskLinux`
transform), and the shared-worker CDP session is kept attached with the same
metadata — Playwright detaches it, which reverted the per-target override.

The hardcoded-Windows `navigator.userAgentData` init script is gone; the
metadata comes from CDP, so `architecture`, `model` and `mobile` follow the
user agent instead of always claiming Windows/x86.

## Install pipeline

`greasy-brands` is szkrabok's own `playwright-core` patch, applied separately
from the rebrowser patches, so it works on a stock, rebrowser-patched or
rebrowser drop-in core. Postinstall order:

```
apply-greasy-brands --strip  ->  apply-patches (rebrowser)  ->  apply-greasy-brands  ->  verify
```

Strip first: the rebrowser patch hunks are line-position based. Marker revisions
are static (`rev=2` for the brands block, `rev=1` for the shared-worker block);
a block of another revision is replaced on install.

## Fixes

- **Unpatched `playwright-core` is detected.** A skipped postinstall used to
  degrade silently. `doctor` reads `lib/coreBundle.js`, the marker list is
  shared, and the launch warns once per process.
- **Test harness no longer leaks browsers.** `launchHeadlessBrowser` killed only
  the wrapper process (flatpak/snap/deb shim), leaving the `bwrap` and chrome
  tree running: 576 processes / ~7 GB after two suite runs. The cleanup now
  kills the process group, scans by `--user-data-dir` as a belt, and sweeps
  crash orphans from earlier runs. 0 leaked processes after the full suites.

## Known limits

- The full-version-list residual above.
- The shared-worker hook is version-fragile: if a future `playwright-core` moves
  the anchors, the core is left untouched and `PATCH_MARKERS` reports the block
  missing rather than half-patching.
- The sandbox default can break a launch on Ubuntu 23.10+ when the resolved
  browser is Playwright's bundled Chromium. Intended, with the opt-out in the
  error message.
